## 6. Conventions [REQUIRED]

<!-- Extracted from Pass 6: Convention Codification -->

### Naming
| Entity | Convention | Example | Confidence |
|---|---|---|---|
| Files | kebab-case | `user-service.ts` | canonical |
| Classes | PascalCase | `UserService` | canonical |
| Functions | camelCase | `getUserById` | canonical |
| Constants | SCREAMING_SNAKE | `MAX_RETRY_COUNT` | majority |
| Database tables | snake_case | `user_profiles` | canonical |

### File Structure
- **Module pattern:** Feature folders (`src/features/{name}/`)
- **Test location:** Co-located (`*.test.ts` next to source)
- **Barrel files:** Used for public module API only

### Error Handling
- **Pattern:** Custom typed Error classes extending `AppError`
- **Logging:** At catch site (service boundary), not at throw site
- **Machine-readable codes:** Yes — every error has a `code: string` field

### Testing
- **Style:** AAA (Arrange / Act / Assert)
- **Mock strategy:** `jest.mock()` for modules, MSW for HTTP
- **Data strategy:** Factory functions in `tests/factories/`
- **Coverage floor:** 80% (enforced in CI)

### API Design
- **URL style:** `/kebab-case` with noun-first path segments
- **Versioning:** Path prefix `/api/v1/`
- **Response envelope:** `{ data, error, meta }` always present
- **Status codes:** Semantic (201 create, 204 delete, 422 validation, 409 conflict)

Quick reference — top critical rules for AI coding agents:

1. **[CONST-SEC-001]** Never generate raw SQL queries — always use the ORM or parameterized queries
2. **[CONST-ARCH-001]** When creating a new service, add it to `src/container.ts` and inject via constructor
3. **[CONST-TEST-001]** Every new public endpoint must have at least one integration test
4. **[CONST-CONV-001]** All errors must extend `AppError` from `src/lib/errors.ts`
5. **[CONST-API-001]** Always wrap responses in `{ data, error, meta }` envelope
