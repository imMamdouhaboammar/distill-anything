# Agent Rule Format

Reference for Step 7 (Agent Rule Synthesis) of the Codebase Constitution skill.

---

## Purpose

Agent rules are the machine-readable output of the Codebase Constitution. They transform extracted invariants and conventions into behavioral instructions that:

1. AI coding agents can follow during code generation
2. Linting tools can enforce mechanically
3. Code reviewers can apply consistently
4. CI pipelines can validate automatically

---

## Rule Schema (YAML)

```yaml
rule:
  id: "CONST-{CAT}-{NNN}"
  category: architecture | security | testing | naming | api | data | infra | convention
  severity: critical | high | medium | low
  trigger: ""         # When does this rule apply? (specific context)
  assertion: ""       # What MUST be true? (positive statement)
  violation_example:  # Code showing the bad pattern
    lang: typescript  # language for syntax highlighting
    code: |
      // BAD: direct SQL string interpolation
      const users = await db.query(`SELECT * FROM users WHERE id = ${userId}`)
  compliant_example:  # Code showing the correct pattern
    lang: typescript
    code: |
      // GOOD: parameterized query
      const users = await db.query('SELECT * FROM users WHERE id = $1', [userId])
  enforcement: lint | type | test | runtime | ci | agent | convention
  source_invariant: "INV-{NNN}"   # backref to extracted invariant
  source_adr: "ADR-{NNN}"         # backref to ADR if applicable
  rationale: ""       # Why this rule exists (1-2 sentences)
  agent_instruction: ""  # Direct instruction text for AI agents
```

---

## Category Codes

| Code | Meaning |
|---|---|
| `ARCH` | Architecture boundary and structure rules |
| `SEC` | Security and access control rules |
| `TEST` | Testing quality and coverage rules |
| `NAME` | Naming convention rules |
| `API` | API design and contract rules |
| `DATA` | Data handling and persistence rules |
| `INFRA` | Infrastructure and deployment rules |
| `CONV` | General coding convention rules |

**ID format:** `CONST-{CATEGORY}-{NNN}` (3 digits, zero-padded)

Examples: `CONST-SEC-001`, `CONST-ARCH-003`, `CONST-TEST-012`

---

## Rule Quality Standards

A well-formed agent rule must:

1. **Be specific** — "validate all inputs" is bad; "validate inputs using Zod schema at the controller layer" is good
2. **Have a violation example** — the bad pattern must be recognizable
3. **Have a compliant example** — the correct pattern must be unambiguous
4. **Derive from evidence** — must reference a source invariant or ADR
5. **State enforcement** — how is this rule caught if violated?
6. **Be atomic** — one rule, one assertion; no compound rules

---

## Minimum Rule Set

Extract at minimum from each category:

| Category | Minimum | Description |
|---|---|---|
| `ARCH` | 5 rules | Layer boundaries, dependency direction, module isolation |
| `SEC` | 5 rules | Auth guards, input validation, secret handling, SQL injection, CORS |
| `TEST` | 3 rules | Test isolation, data factories, coverage floor |
| `NAME` | 3 rules | File names, class names, function names |
| `API` | 3 rules | Response shape, status codes, versioning |
| `DATA` | 3 rules | Query patterns, transaction boundaries, migration rules |
| `CONV` | 3 rules | Error handling, logging, config access |

Total minimum: **25 rules**

## Agent Instruction Style

The `agent_instruction` field is the actionable directive for an AI coding agent. Write it as:

- **Imperative**: "Always...", "Never...", "When X, do Y..."
- **Specific**: Reference exact patterns, file locations, or APIs
- **Bounded**: Apply only to the stated trigger context

```yaml
# Example
agent_instruction: >
  When generating a new service class, always inject dependencies via the constructor
  and register the class in src/container.ts. Never instantiate services with `new`
  at the call site. See src/users/users.service.ts for a reference implementation.
```
