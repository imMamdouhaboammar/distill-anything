# 02 — Stage 1 & Stage 2: Ingest & Deterministic Signal Extractor

## 1. Objective
Convert an arbitrary repository (potentially 10,000+ files) into a dense, deterministic `SignalBundle` capped at **60,000 tokens** containing only the highest-leverage architectural code, edge-case tests, and performance/refactor git diffs.

Zero LLM calls occur in Stages 1 and 2.

## 2. Stage 1: Ingest & Repo Profiler (`01-ingest.ts`)

### 2.1 Acquisition
- If `<source>` is a remote URL:
  - Clone into an OS temp directory (`mkdtemp`) using:
    `git clone --depth <git-depth> --filter=blob:none --no-tags <url> <tmpDir>`
  - Record exact `HEAD` commit SHA (`git rev-parse HEAD`) for deterministic provenance.
- If `<source>` is a local directory:
  - Operate read-only. Never modify working tree or git index.
- Apply `--subpath` if provided; validate path exists and stays inside repo root (prevent path traversal).

### 2.2 Noise & Generated Code Exclusion
Always ignore:
- `.git/`, `node_modules/`, `dist/`, `build/`, `target/`, `.next/`, `__pycache__/`, `.venv/`, `vendor/`, `third_party/`
- Lockfiles (`package-lock.json`, `bun.lock`, `yarn.lock`, `Cargo.lock`, `go.sum`, `poetry.lock`)
- Minified or bundled files (`*.min.js`, `*.bundle.js`, `*.map`)
- Binary assets (images, fonts, `.wasm`, `.pdf`, `.onnx`, `.safetensors`, `.bin`)
- Generated protobuf/GraphQL/OpenAPI stubs (detected via header scan in first 5 lines for `DO NOT EDIT`, `@generated`, `Code generated by`)
- Any file exceeding **250 KB** or **3,000 lines** (logged as `skipped_oversized` in `RepoProfile`).

### 2.3 Maturity & Context Classifier (Deterministic Heuristics)
Compute an objective `MaturityProfile` (never a subjective score) so downstream stages know the repo's operating environment:
- `hasCiWorkflows`: presence of `.github/workflows/*.yml`, `.gitlab-ci.yml`, `Makefile`
- `hasBenchmarks`: presence of `bench/`, `benches/`, `benchmarks/`, or `*.bench.*`
- `hasStrictTyping`: `strict: true` in `tsconfig.json`, `mypy.ini`/`pyrightconfig.json`, or statically typed language (`rust`, `go`, `cpp`)
- `hasTests`: ratio of test files to source files
- `experimentalMarkers`: count of `TODO`, `FIXME`, `HACK`, `XXX` per 1,000 LOC, plus presence of `notebooks/`, `*.ipynb`, `paper/`, `experiments/`
- `classification`:
  - `production`: `hasCiWorkflows && hasTests && experimentalMarkersPerKloc < 8`
  - `hybrid`: mix of core library + research/experimental folders
  - `research_prototype`: high notebook/experiment ratio or missing CI/tests

## 3. Stage 2: Deterministic Signal Extractor (`02-signals/`)

The 60,000-token budget is split deterministically across four buckets:
- **Bucket A — Core Architecture Files (Fan-in + Complexity)**: `30,000 tokens` (up to `--max-files * 0.65`)
- **Bucket B — High-Signal Git Diffs**: `15,000 tokens` (up to `--max-commits`)
- **Bucket C — Edge-Case Test Files**: `10,000 tokens` (up to `--max-files * 0.25`)
- **Bucket D — Architecture Docs / ADRs / README Excerpts**: `5,000 tokens`

Unused tokens from Bucket B/C/D roll over into Bucket A.

### 3.1 Bucket A: AST Import Graph & Fan-In Scoring (`ast-graph.ts`)
1. Parse every non-test source file with `web-tree-sitter` using its language grammar.
2. Extract:
   - Internal relative imports/includes -> build directed dependency graph `G(V, E)`.
   - Exported symbols (classes, structs, traits, interfaces, functions, types).
   - Low-level / high-craftsmanship AST indicators:
     - Rust: `unsafe_block`, `macro_definition`, `trait_item`, `impl_item`
     - TS/JS: generic type constraints, `Proxy`, `Worker`, `SharedArrayBuffer`, `AbortController`, custom Error subclasses
     - Python: `__slots__`, metaclasses, `asyncio` primitives, `ctypes`/`cffi`/`triton`/`torch.autograd.Function`, context managers
     - Go: `sync.Pool`, `atomic`, `chan`, `select`, `unsafe.Pointer`, custom interfaces
     - C++: templates, `std::atomic`, `mmap`, SIMD intrinsics, custom allocators
3. Score every source file $f$:
   $$\text{Score}(f) = 3.0 \cdot \ln(1 + \text{fanIn}(f)) + 2.0 \cdot \text{craftDensity}(f) + 1.5 \cdot \ln(1 + \text{exportedTypes}(f)) - 0.5 \cdot \text{boilerplatePenalty}(f)$$
   - `fanIn(f)`: number of other internal files importing `f`.
   - `craftDensity(f)`: normalized count of high-craftsmanship AST nodes per 100 LOC.
   - `boilerplatePenalty(f)`: penalty if file is purely re-exports (`index.ts` with only `export * from`), CLI argument parsing, or static lookup tables.
4. Select top files until Bucket A token limit is reached.
5. **Smart File Truncation**: If a top-ranked file exceeds 4,000 tokens, keep full file header + all type/interface/struct definitions + full bodies of functions containing high-craftsmanship nodes, replacing trivial helper bodies with `/* [elided lines X-Y] */` while preserving exact original line numbers on every retained line.

### 3.2 Bucket B: High-Signal Git Diff Mining (`git-miner.ts`)
Run `git log -n <git-depth> --no-merges --format="%H|%s|%ad" --date=short`:
1. Filter commits whose subject or body matches architectural/engineering keywords (case-insensitive regex):
   `\b(perf|optimi[sz]|race|deadlock|lock-?free|zero-?copy|memory|leak|cache|concurren|async|refactor|architect|invariant|edge[- ]case|retry|backpressure|stream|pool|alloc|latency|throughput|batch)\b`
2. Exclude mass formatting commits (`filesChanged > 15` or `insertions + deletions > 1,200`) and version bump commits (`chore(release)`, `bump version`).
3. Score remaining commits by:
   - Keyword match weight (performance/concurrency/memory keywords rank higher than generic `refactor`).
   - Presence of body explanation (`body.length > 80` chars gets `+3.0` bonus — engineers explaining *why* in commit messages is the highest-value signal).
   - Touching files already ranked in Bucket A (`+2.0` bonus).
4. Extract unified diff (`git show --stat -U5 <sha>`) for top commits, stripping lockfile/snapshot hunks, until Bucket B token limit is reached.

### 3.3 Bucket C: Edge-Case Test Hunter (`test-hunter.ts`)
1. Identify test files (`*.test.*`, `*.spec.*`, `*_test.go`, `test_*.py`, `tests/**`).
2. Rank test files by:
   - Importing Bucket A core files.
   - Density of edge-case keywords inside test names/descriptions: `race`, `concurrent`, `overflow`, `timeout`, `retry`, `corrupt`, `empty`, `boundary`, `crash`, `recover`, `fuzz`, `property`, `invariant`, `deadlock`, `cancel`, `abort`.
3. Select top test files (with line numbers) until Bucket C token limit is reached.

### 3.4 Bucket D: Architectural Documentation (`bundler.ts`)
Collect if present (prioritized in order):
1. `docs/adr/*.md`, `docs/architecture*.md`, `ARCHITECTURE.md`, `DESIGN.md`
2. Relevant sections of `README.md` (Architecture, Design Goals, Internals, Benchmarks — strip installation/badges/license sections).

## 4. Exact Line-Number Formatting
Every code file placed into `SignalBundle` MUST be prefixed with 1-indexed line numbers:
```text
0001 | import { RingBuffer } from "./ring";
0002 | export class BackpressureQueue<T> {
```

This guarantees Stage 3 can cite exact `startLine` and `endLine` values that Stage 3's deterministic grounder can verify.
